# Onboarding package

`@apparent/onboarding` is a TypeScript setup and practice owner. It exports a pure controller and React contribution factory. It owns versioned progress, resume/defer/completion, coaching stages, practice association, and manual paste confirmation. It consumes the exact packed public `@apparent/record/capabilities` contract; it imports no Record implementation, EngineClient, Electron API, or Rust.

## Build and tests

Run `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, and `npm pack --dry-run` in this directory. The development dependency is the committed public Record tarball `vendor/record-0.1.0-afd73fb.tgz`, packed from candidate PR #674 head `afd73fbdca110ee866d32b062219cab762f20f17`, SHA-256 `61bddb5d86bf71cb9566c0071f2e22e2e226553291d1bd5c90eaa45237853ab3`. The lockfile pins its packed declarations/runtime; Onboarding install does not build the Record source tree. Refresh this pin to the landed public package artifact before integrating #669 if #674 changes. Tests use `createRecordFixture` from that package and mount the React contribution in jsdom for real button clicks. This proves fixture behavior, not installed behavior. No Cargo/rustc is required.

The shell injects the canonical `Button` from `@apparent/ui/button` and loads `@apparent/onboarding/styles.css`. That keeps this owner independently typecheckable/buildable while sharing canonical controls and design tokens at composition. Record is an optional package peer so a clean package import can validate the isolated contribution; the host must install the exact compatible `@apparent/record` package to run artifact-open verification and the complete lesson.

## Record contract mapping and adoption limits

Onboarding imports the public capabilities from the packed Record package. Commands use a unique request ID and the observed provider epoch/revision. `accepted` means dispatch only; only provider facts or `applied` plus readback can advance a milestone. Disposal detaches observation and requests cancellation only for a still-armed reservation; it never stops a capture.

Practice reserves the next shortcut as local-only before prompting the user, persists its identity, and accepts only the newly consumed matching capture with local-only readback and shortcut evidence. Deferral/disposal cancels an unconsumed reservation; consumed capture is never stopped. The fixture proves the policy consumer, not a production adapter: no native shortcut reservation producer or delivery enforcement/readback adapter exists yet. Permission continuation requires all required requirements usable now with no relaunch pending. Shortcut continuation requires a nonempty effective binding, no draft, and confirmed registration; an externally-managed boolean alone is not proof. Pen selection advances only after an `applied` result whose snapshot reads back the selected effective value and the animation completes (or reduced motion is enabled).

Candidate #674 names the donor's coral, purple, blue, and green palette as `PenColor`, separates it from drawing tool modes, and supplies typed picker and accepted-stroke outcomes. Onboarding uses that exact type and fixture readback. The fixture proves consumer behavior only; the production pen writer, native picker/stroke mapping, shortcut reservation and enforced local-only delivery producers remain unavailable.

Processing, save and copy are separate outcomes on the associated capture. Paste confirmation is a manual user action; no private composer is observed. Locate calls `hasConfirmedArtifactOpen(snapshot, captureId)`, which requires the saved exact capture and current artifact identity with `viewer-ack` or `os-observation`. A matching proof completes automatically after the user confirms paste. Dispatch alone never completes the lesson. #665 added the typed fact/helper and fixture coverage; no production provider emits the confirmation yet. Installed setup remains pending at Locate until Record maps trusted viewer acknowledgement or supported OS observation to the saved artifact identity. Never infer opened/watched from focus, process, path, or dispatch success.

Practice uses the candidate's request-scoped arm/cancel facts and checks the consumed admission ID against the exact capture, shortcut fact, and enforced `delivery: "local-only"` readback. It does not issue a second menu start. This candidate fixture covers consumer policy only; the installed adapter must enforce these facts or refuse adoption.

## Persistence, host adoption and rollback

`ProgressStore` requires read and compare-and-swap `(revision,value)`, distinguishing saved, conflict/current snapshot, and unknown publication. Unknown is not success. The only store in tests is in-memory. Installed progress must use the sole transactional writer after verified cutover; no filesystem read/modify/write or competing writer is supplied. The shell provides activation reasons (`firstLaunch`, `settings`, `resume`) and declarative coach placement, then renders `createOnboardingContribution({controller, Button, close, onManualPasteInstructions})`. No arbitrary IPC/window/URL/filesystem effect is exposed. There is no production host/preload adapter or second installed surface.

The shipped Preview 0.12.2 journey in the read-only release-baseline checkout is the design donor for frog/puddle artwork, approved copy, and pen-hop motion. Only the frog asset is copied here. Host routing remains unchanged until this contribution and its adapters are accepted. Rollback removes the host contribution registration and returns to the existing setup route; progress is not dual-written or migrated by this package.

Remove the donor only after typed Record capabilities, truthful local-only admission, production artifact-open evidence, transactional progress writer, host contribution/preload, shared UI checks and affected native seams are verified; existing resume/defer/completion state is preserved; and every source/build/package consumer has moved. A passing fixture package is not installed adoption or native proof.
